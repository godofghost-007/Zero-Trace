1. Executive Summary

ZeroTrace is a unified cyber defense platform combining three integrated modules — Recon (attack surface
discovery), Intel (AI-powered vulnerability prioritization), and Guard (LLM security middleware) — into a single
command center with a shared asset inventory, correlated threat intelligence, and one Operational Readiness Score.

Built for organizations that cannot afford enterprise SOC tooling, ZeroTrace runs on a single laptop via Docker
Compose, requires zero GPU, and costs nothing to deploy. It is designed to address three critical gaps identified in 2026
cybersecurity research: asset visibility blind spots, CVE prioritization failure, and unmonitored LLM attack
vectors.


   "They leave no trace. Because we found them first."




2. The ZeroTrace Philosophy

ZeroTrace operates on the principle that the best defense is total visibility — you cannot stop what you cannot see. It
traces every asset, every vulnerability, and every AI attack vector back to a single source of truth.

 PRINCIPLE                 MEANING


 Zero                      Zero blind spots. Zero unpatched critical vulns. Zero AI attacks unblocked.

 Trace                     Every asset traced. Every threat traced. Every attack traced to its origin.

4. Why ZeroTrace? — The Problem Landscape

4.1 The Asset Visibility Crisis

Organizations cannot protect assets they do not know exist. Shadow IT — the use of IT systems without explicit
organizational approval — has become a critical issue with cloud computing, introducing significant security
vulnerabilities due to lack of oversight and proper security measures.

According to the Intruder 2026 Attack Surface Management Index, which analyzed anonymized data from
3,000 organizations:

     54% of SMEs (1–250 employees) had at least one attack surface exposure in the past 12 months

     26% had MySQL databases exposed to the internet
     26% exposed risky ports and services

     20% exposed HTTP admin panels

As organizations grow, the number of internet-facing assets increases sharply, making security management
significantly more complex.


4.2 The Vulnerability Prioritization Crisis

Organizations face approximately          135 new CVEs per day       — a 40% year-on-year increase — with over
 48,000 new CVEs      published in 2025 alone. Security teams following CVSS-based prioritization must address
thousands of vulnerabilities that pose little real-world risk.

Research has established that CVSS-based prioritization is highly inefficient, with efficiency measurements (0.2–
0.5%) being even lower than previous research (3.9%). The Common Vulnerability Scoring System relies on manually
assigned metrics that are often incomplete or inconsistent across different reporters.

Mean Time to Remediate (MTTR) stretches to 55–72 days for critical vulnerabilities (with the 74-day figure from
Picus representing the mean across all severity levels). Research shows that vulnerabilities with high exploitation
probability (EPSS > 0.7) actually carry a higher average remediation time (109 days) than low-probability ones —
meaning teams are systematically patching the wrong things first.

Picus    Security     reports   that   organizations    using    validation-led   approaches   can   reduce   MTTR    from
 74 days → 14 days and clear 86% of patch backlogs.


4.3 The LLM Security Crisis

While nearly 80% of organizations are using AI in some form, only 6% have implemented a comprehensive AI
security strategy. Nearly two-thirds ( 64% ) of organizations lack full visibility into their AI risks, and       54%    of
enterprises have already experienced a confirmed AI agent security incident or near-miss.

Prompt injection poses a serious threat to the reliability and safety of LLM agents. Jailbreak attacks that bypass built-in
safety mechanisms are increasingly recognized as a tangible threat across industries. Red team studies have identified
five dominant failure patterns: partial refusals (34%), hidden compliance (22%), no output (18%), and misleading
responses (15%).

The MDPI Electronics journal has documented various injection techniques where attackers embed malicious
instructions within prompts to bypass security filters and manipulate LLM outputs.

10. The Operational Readiness Score                                                  FIXED




ZeroTrace computes a single Operational Readiness Score from three traces:



   Score = 100 − (0.40 × Asset Exposure Index + 0.40 × Vulnerability Urgency Index + 0.20
                                                    × AI Threat Exposure Index)



Where:

   Asset Exposure Index = (exposed services / total services) × 100

   Vulnerability Urgency Index = Σ(ML Exploit Probability × CVSS Severity) / total assets × 100

   AI Threat Exposure Index = (unblocked attack attempts / total LLM requests) × 100


   Formula Correction (v2.0): The original formula used "AI Threat Block Rate" — a defensive success metric
   — which was logically inverted (better defense = lower score). This has been corrected to "AI Threat Exposure
   Index" — the proportion of attacks that were not blocked. All three terms now represent negative factors that
   subtract from the score, making the formula directionally consistent.

14.4 SQLite Audit Log Integrity


   Row N: timestamp | action | details | hash = SHA256(Row N-1 hash + Row N data)

   Row N+1: timestamp | action | details | hash = SHA256(Row N hash + Row N+1 data)

   Any deletion or modification of a row breaks the chain, detectable by a verify_audit_integrity() function.

16.2 Why This Stack in 2026?

AI Coding Agent (Qwen2.5-Coder)
Qwen2.5-Coder 7B Instruct is the clear winner at this size tier, scoring in the high 80s on HumanEval. It leads the
CRUXEval-Output-CoT leaderboard with a score of 0.560. At Q4_K_M quantization, it uses ~4.7 GB and runs
efficiently on CPU.


Dashboard (HTMX + Alpine.js)
HTMX handles server-driven updates at 14KB; Alpine.js manages client-side state at 15KB. Together they replace most
single-page applications. This eliminates the need for Node.js build tools and 500MB+ of node_modules .


Database Architecture (PostgreSQL + Redis + SQLite)

   PostgreSQL handles complex relational queries (assets ↔ CVEs)

   Redis (Valkey) provides in-memory rate limiting, score caching, and event bus

Appendix A: Glossary of Terms

 TERM        DEFINITION


 ASM         Attack Surface Management — continuous discovery and monitoring of all internet-facing assets


 CPE         Common Platform Enumeration — standardized naming scheme for software and hardware

 CVE         Common Vulnerabilities and Exposures — publicly disclosed cybersecurity vulnerabilities

 CVSS        Common Vulnerability Scoring System — framework for rating vulnerability severity (0–10)


 EPSS        Exploit Prediction Scoring System — probability score (0–1) of a vulnerability being exploited

 HTMX        Lightweight JavaScript library (14KB) for dynamic UI updates without full page reload

 JWT         JSON Web Token — compact token for securely transmitting information


 KEV         Known Exploited Vulnerabilities — CISA catalog of vulnerabilities actively exploited

 LLM         Large Language Model — AI model trained on vast text data (e.g., GPT, Claude, Qwen)

 MTTR        Mean Time to Remediate — average time to fix a vulnerability


 NVD         National Vulnerability Database — US government repository of CVE data

 ONNX        Open Neural Network Exchange — format for ML model interoperability

 ORM         Object-Relational Mapping — technique for converting data between incompatible systems


 Q4_K_M      Quantization level for LLMs — 4-bit with medium K-means, balancing size and quality

 RBAC        Role-Based Access Control — restricts system access based on user roles

 Shadow IT   IT systems used without explicit organizational approval or oversight


 SME         Small and Medium Enterprise — organizations with 1–250 employees
